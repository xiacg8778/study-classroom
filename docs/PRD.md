# AI 教育 Web App 增量 PRD

> 文档类型：简单 PRD（MVP）  
> 项目状态：需求定义，非上线声明  
> 依据：现有 C2.1 总纲、Phase 2 静态审计、Phase 3 隔离整合验收及工作区现状材料

## 1. 项目信息

- **Language**：中文
- **Programming Language**：Vite + React + MUI + Tailwind CSS
- **Project Name**：`ai_education_webapp`
- **目标终端**：桌面浏览器 + 手机 H5；响应式单代码库
- **原始需求复述**：在现有教育中心之上新增一个面向家庭学习的 AI 教育 Web App。用户可选择年级与教材、在授权范围内阅读原书，通过聊天让 AI 逐课讲解或把难题转换为微课堂，获得动画/语音辅助课程，完成可视化随堂练习与 Quiz，由 AI 给出可解释批改，沉淀错题与知识图谱，并得到个性化下一课建议。

### 1.1 已知系统事实与产品约束

1. `kernel-10` 必须继续作为唯一课程调度者；前端、Agent、学科能力和参考项目均不得形成第二调度器。
2. Agent 只能输出 proposal/candidate；组件 24 是业务登记门面，物理状态提交由教育中心宿主完成。
3. 当前尚无真实正式 registry、`kernel-10` 新路由与学习状态写入；PostgreSQL/BFF/Outbox 仍未部署，不能在产品中宣称已上线。
4. 组件 25、34 仅在隔离 shadow overlay 中登记且 flag 为 `false`；组件 35、36 已按能力原子合并至宿主 2.5.0，但未正式激活；组件 26、37 继续 HOLD。
5. MVP 必须区分“可交互演示/候选结果”与“已提交事实”。未收到宿主 commit 回执时，界面不得显示“已保存”“已加入复测队列”或“已掌握”。

### 1.2 已确认 MVP 决策

1. **运行形态**：首版为本地受控 MVP，不建设账号、跨设备同步或监护人远程查看，不宣称云端长期记忆。
2. **教材来源**：首版使用演示教材 + 用户合法持有的本地 PDF；演示教材必须有清晰授权，本地 PDF 默认不上传、不公开分发。
3. **题目输入**：支持文本输入、本地 PDF 选区，以及完全在浏览器本地运行的 JPG/PNG 印刷体 OCR；识别结果必须经用户校对确认，手写体与复杂公式不承诺准确。
4. **语音方案**：P0 使用浏览器本地 TTS，必须支持播放/暂停、静音，并保留文字内容作为等价替代。

## 2. 产品定义

### 2.1 产品定位

一个以教材为上下文、以证据为依据、以聊天为主要入口的家庭 AI 学习工作台。它不是答案搜索器，也不以“刷完课程”为成功，而是帮助学习者完成“选课—理解—练习—取证—纠错—安排下一课”的连续闭环。

### 2.2 Product Goals

1. **降低理解门槛**：让学生能从教材页、章节或一道难题出发，在 3 次交互内进入与当前年级、教材和知识点对应的讲解或微课堂。
2. **形成可解释学习闭环**：每个已完成学习单元必须产生可追溯的作答/复述证据、批改依据、错因建议和唯一下一课 proposal；无证据不判掌握。
3. **建立安全、可持续的家庭学习入口**：桌面与手机 H5 均可顺畅完成核心任务，同时守住教材版权、未成年人隐私、内容安全和 C2.1 唯一调度/提交边界。

### 2.3 非目标

- 不承诺覆盖全国所有教材版本或直接提供无授权教材全文。
- 不替学生写作业、作文或绕过思考直接给最终答案。
- 不做医学、心理、智力或人格诊断，不做学生排名羞辱。
- MVP 不启用组件 26 阶段家庭评估与组件 37 OpenMAIC runtime。
- MVP 不宣称已有正式多租户云数据库、可靠消息队列或自动跨设备同步。

## 3. 目标用户

| 用户 | 核心任务 | 主要痛点 | 产品价值 |
|---|---|---|---|
| 小学高年级至高中学生 | 看教材、听讲、问难题、练习、订正 | 不知道卡在哪里；答案看懂但不会独立做；手机端操作负担大 | 分步讲解、一次一个动作、可视化练习、证据化反馈 |
| 家长/监护人 | 配置教材和边界、了解进展、协助下一步 | 难判断是真会还是“听懂了”；担心 AI 直接给答案和隐私泄露 | 客观证据、低压力建议、授权与数据控制 |
| 内容/教研运营者 | 维护教材元数据、课程模板、安全规则 | 教材版本复杂，授权与 AI 内容质量难治理 | 结构化来源、版本状态、审核与下架机制 |

### 3.1 User Stories

1. **As a 学生, I want 选择自己的年级、学科和教材版本并定位到当前课 so that AI 的讲解不会脱离校内进度。**
2. **As a 学生, I want 在教材页旁边直接提问或上传一道难题生成微课堂 so that 我能按步骤理解而不是只拿答案。**
3. **As a 学生, I want 完成可视化随堂练习并看到基于作答过程的批改 so that 我知道错在概念、方法还是步骤。**
4. **As a 家长, I want 查看有证据引用的错题与下一课建议 so that 我能做一件低压力、可执行的配合。**
5. **As a 监护人, I want 控制孩子的数据、教材来源和 AI 功能权限 so that 使用过程符合家庭边界和未成年人保护要求。**

## 4. 端到端核心旅程

### 4.1 首次进入与教材绑定

1. 监护人确认隐私说明、数据范围和基础学习边界。
2. 选择学习者年级、学科、教材版本；每个孩子绑定独立 `learnerId`。
3. 系统展示教材可用状态：**已授权可读 / 用户本地导入 / 仅目录可用 / 暂不可用**。
4. 学生选择章节或当前课；若对象不明确，最多追问 3 个问题后给出最小可行动入口。

### 4.2 教材学习与聊天讲解

1. 学生在阅读器查看获授权教材页或本地文件，并可选中段落/题目作为上下文。
2. 聊天区提供“解释这一段”“举个例子”“换种讲法”“我没听懂”等快捷动作。
3. Web App 将上下文和学习意图提交给 `kernel-10`；一次只运行一个学习范式。
4. AI 分步讲解，一次推进一个小动作；关键点讲完要求学生复述或完成小练习。

### 4.3 难题转微课堂

1. 学生输入文本难题、从本地 PDF 教材页选择题目，或导入 JPG/PNG 图片在浏览器本地完成 OCR；识别文本经学生校对确认后才能作为题目。
2. 系统把题目、PDF 选区和参考答案视为材料而非指令，完成内容安全和提示注入过滤。
3. `kernel-10` 选择题解支架或概念掌握范式，生成受控的微课堂 proposal：学习目标、分步讲解卡、图示/轻动画脚本、练习与复述点。
4. MVP 使用前端步骤动画和浏览器本地 TTS 进行语音播放；不得把该展示直接当作 OpenMAIC runtime 已启用。

### 4.4 Quiz、批改与错题

1. 学生完成 3–5 题随堂 Quiz；系统记录题目曝光、原始作答、用时和提示次数。
2. AI 给出逐题批改 proposal：对错、依据、思路反馈、R1–R11 错因建议；不以“粗心”作为主错因。
3. 系统要求学生说明关键步骤或复述；“学完了/我会了”不作为掌握证据。
4. 组件 24 形成待登记的错题卡、证据和快照 proposal；只有宿主 commit 成功后，错题本才显示“已归档”。

### 4.5 知识图谱与下一课

1. 知识图谱展示教材知识点、前置关系、证据状态和待复测关系；AI 生成内容不得自动变成事实节点。
2. `kernel-10` 基于证据生成唯一调度 proposal，主路径限定为 P1–P9 之一，可带最多一个辅路径。
3. 界面展示“为什么推荐”“依据哪条证据”“下一步 5–30 分钟做什么”；状态差时优先 P9，缩短为 2–10 分钟。
4. 只有正式提交回执存在时才更新下一课与队列；否则明确显示“建议待确认/尚未保存”。

## 5. 信息架构

### 5.1 一级导航

| 模块 | 主要内容 | 桌面端 | 手机 H5 |
|---|---|---|---|
| 今日学习 | 当前课、预计时长、继续学习、待复测 | 首页主面板 | 默认首屏 |
| 教材库 | 年级/学科/版本选择、授权状态、最近阅读 | 网格/筛选 | 卡片+底部筛选 |
| 学习课堂 | 教材阅读、AI 聊天、微课堂、Quiz | 非对称三栏学习桌 | 教材主画布+底部任务轨道 |
| 错题本 | 错题卡、错因、订正、复测时间与状态 | 表格+详情抽屉 | 卡片流+详情页 |
| 知识图谱 | 节点关系、掌握证据、薄弱前置 | 可缩放图谱+侧栏 | 聚焦路径/列表优先，图谱次级 |
| 我的/家长 | 学习者、授权、数据导出删除、功能状态 | 设置页 | 设置页 |

### 5.2 学习课堂内部结构

- 顶部：返回、教材/章节、学习状态、预计时长。
- 主区：教材页或微课堂卡片。
- 辅区：AI 聊天、上下文引用、快捷提问。
- 底部任务条：当前唯一动作，如“先说说你的思路”“完成第 2 题”。
- 学习收尾：Quiz → 证据摘要 → 错题/订正 → 下一课 proposal。

## 6. Requirements Pool

### P0 — Must have

#### P0.1 响应式基础与身份边界
- 必须支持常见桌面宽度和 360px 及以上手机视口；核心旅程不得依赖横向滚动。
- 必须区分监护人与学习者操作；每个孩子使用独立 `learnerId`，不可串用历史记录。
- 必须显示当前运行模式与能力状态，禁止把 shadow/HOLD/未提交能力包装为已上线。

#### P0.2 教材选择与合规阅读
- 必须支持年级、学科、教材版本和章节选择，并展示来源、版本与授权状态。
- 仅允许展示已获授权内容或用户合法持有的本地文件；“仅目录可用”时不得提供全文。
- 本地教材默认仅在浏览器会话内处理；未经单独同意不得上传或长期保存。

#### P0.3 教材上下文聊天与难题微课堂
- 必须支持文本提问、本地 PDF 选区引用，以及浏览器本地 JPG/PNG 印刷体 OCR；图片和未确认草稿不得上传或持久化，识别结果必须可校对。
- 必须由 `kernel-10` 决定范式与调用顺序；一次只推进一个学习动作。
- 必须提供分步讲解、换讲法、复述检查、可视化步骤卡和浏览器本地 TTS；语音可播放/暂停/静音，且始终提供等价文字内容。
- 不得默认直接给最终答案；学生明确请求答案时，仍应先确认思路或提供第一步入口。

#### P0.4 Quiz 与可解释 AI 批改
- 每课必须支持 3–5 题 Quiz，至少覆盖选择/填空及一种分步作答。
- 必须保存或暂存题目曝光、原始作答、提示次数和批改依据；批改结果明确标记为 AI proposal，直至宿主验收。
- 无复述/解释证据不得判 L3，无迁移证据不得判 L4；证据不足使用“暂无法判断”。

#### P0.5 错题本
- 必须按统一 8 字段错题卡展示题目、原答与思路、R 错因、正确入口、避免方法、识别线索、是否反复、复测安排。
- 必须区分“待登记 / 已归档 / 队列同步中 / 已进入复测队列”；状态完全取决于真实 commit/queue 回执。
- 必须支持按学科、章节、错因和复测状态筛选。

#### P0.6 知识图谱与个性化下一课
- 必须展示知识点、前置关系、证据状态和关联错题；数据来源可追溯。
- 下一课必须由 `kernel-10` 输出唯一决策，限定 P1–P9，展示证据与理由。
- 低于 L3 不得推进同一依赖链新内容；R10/状态差时 P9 优先。

#### P0.7 C2.1 接入门禁
- Agent 必须固定为 proposal-only；不得直接写数据库、正式 registry、学习快照或路由。
- 组件 24 必须是业务登记门面，宿主必须执行权限、Schema、幂等键和 `baseContextVersion` 校验后再物理提交。
- 25/34 flag 默认关闭；35/36 在正式注册与主链验证前不得声称激活；26/37 不得进入 MVP 用户主链。
- 所有未实现状态必须 fail-closed，并提供可理解的用户降级提示。

#### P0.8 未成年人安全与可控性
- 必须提供监护人同意、敏感内容过滤、会话退出、数据导出与删除入口。
- 必须屏蔽羞辱、比较、威胁、诊断标签、成人不适内容和危险操作指导。
- 检测到自伤/伤人或紧急安全信号时，必须停止普通学习分析，提示联系监护人和当地紧急/专业支持；不得继续自动评估。

### P1 — Should have

- **正式状态闭环**：在宿主 registry、`kernel-10` 路由和 24→host commit 全链验收后，启用跨会话恢复与真实复测队列。
- **图片拍题/OCR（已完成本地版+基线分级）**：支持相机/图片导入、OCR 校对与手工修订；识别结果按置信度三档分级提示（较好/存疑/低可信），低档给出手写体、运算符、上下标等针对性核对建议与手动输入引导；几乎无有效文字时直接提示重拍或手输。OCR 结果仍按不可信材料处理，原图和未确认草稿不持久化。已建立可复测基线（见 QA_REPORT）：清晰印刷体置信度 92-93%、字符准确率约 84.5%；带扰动手写代理置信度 56-62%、准确率约 59%；含数学符号公式代理置信度 77%、准确率 74-84%——手写体与复杂公式不承诺准确，靠分级提示兜底。
- **教材阅读增强（本地 PDF 首批已完成）**：已支持全文文本搜索、页码定位、当前会话书签、缩略图导航，以及会话内划线与朗读进度；弱网恢复仍待后续。搜索、书签、缩略图、划线和朗读进度均不上传、不持久化，关闭文档或切换学习者即清除。
- **本地中断恢复（已完成，自动恢复）**：刷新后自动恢复学习者/教材/课程并直接回到课堂，顶部显示「已自动恢复」通知（可退出会话）；曾打开的本地 PDF 仅提示文件名、需重新选择（字节不持久化）。路由懒加载失败自动重试一次，仍失败提供「重新加载页面」降级 UI，不白屏。恢复数据仅存 sessionStorage（非敏感指针），隐私模式自动降级。
- **课程媒体增强**：在浏览器本地 TTS 基础上评估经授权的高质量 TTS、多角色语音、结构化图解和轻动画模板；提供字幕、倍速、暂停和静音。
- **图谱交互增强**：从错题跳转前置知识、查看证据时间线、对比复测前后变化。
- **家长摘要**：仅根据已提交证据生成每课摘要；一次只给一件低压力建议。
- **25/34 分阶段启用**：分别完成包级真实运行证据、幂等/版本/多会话回归后再从 shadow 晋级。

### P2 — Nice to have

- 组件 37 完成 callback、乱序/重复/旧版本、kernel closure、24 prepare 和回滚验证后，接入 OpenMAIC 互动课堂。
- 组件 26 补齐默认脱敏、事实/推测/待验证/建议四分离、危机升级、家长复核和多源冲突门禁后，提供阶段报告。
- 教材内容离线缓存、多设备同步、家长周报、打印错题册。
- 基于已授权题库生成变式题、语音问答、学科专用交互画板。
- 非竞争性轻游戏化，如连续完成最小任务、知识点探索徽章；不做公开排行或攀比。

## 7. MVP 验收标准

### 7.1 核心旅程

1. 在桌面与 360px 手机视口各完成一次：选年级/教材 → 打开一课 → 基于教材提问 → 生成微课堂 → 完成 Quiz → 查看批改 → 形成错题候选 → 查看图谱 → 获得下一课 proposal；阻断性错误为 0。
2. 新用户从进入首页到打开首个学习单元，正常网络下不超过 3 分钟、关键选择不超过 5 步。
3. 从一道文本难题、本地 PDF 选区或已确认的本地 OCR 文本进入首张微课堂步骤卡不超过 3 次用户交互；OCR 入口必须明确标注“本地识别、不上传、不保存”。
4. 100% 学习单元一次只呈现一个当前动作；100% 下一课输出只有一个主路径 P1–P9。

### 7.2 教学与证据正确性

5. 抽测至少 30 个学习单元：无证据判 L3/L4、低于 L3 同链推进、把“学完了”当证据的违规数均为 0。
6. 抽测至少 50 道错题：统一 8 字段完整率 ≥95%；主错因使用“粗心”的数量为 0。
7. 每条批改均能定位到题目和原始作答；每条下一课建议均能展示至少 1 条证据引用或明确标记“证据不足”。

### 7.3 权限、状态与可靠性

8. 越权 commit、Agent 直写、旧 `baseContextVersion`、相同幂等键不同 payload 必须 100% 被拒绝；相同幂等键相同 payload 不产生重复记录。
9. 未收到 commit 回执的所有候选均不得显示为“已保存/已掌握/已入队”；自动化 UI 测试违规数为 0。
10. 25/34 flags 在默认配置下均为关闭；26/37 路由命中数为 0；35/36 无正式注册时仅显示“能力已合并、未激活”。

### 7.4 响应式、可用性与安全

11. Chrome、Safari、Edge 最近两个主要版本完成核心流程；核心页面在 360px、768px、1280px 三档无内容遮挡和关键按钮不可达。
12. 键盘可完成主要交互，媒体均有字幕/文本替代，核心文字与控件符合 WCAG 2.1 AA 对比度目标。
13. 教材全文无授权泄露数为 0；跨 `learnerId` 数据泄露数为 0；提示注入、XSS、危险内容、越权引用安全负例必须全部拒绝或安全降级。
14. 监护人可完成数据导出和删除；删除结果必须显示真实执行状态，不得仅给成功文案。

## 8. 数据、版权与安全边界

### 8.1 数据边界

- **最小化采集**：MVP 仅采集实现学习所需的年级、教材、作答、提示使用、学习证据和必要技术日志；默认不采集真实姓名、学校、精确位置、通讯录。
- **身份隔离**：`workspaceId` 是家庭边界，`learnerId` 是孩子边界，`sessionId` 不是长期身份；严禁跨学习者拼接上下文。
- **证据/快照/报告三分离**：原始作答与证据追加保存；快照可更新但必须引用证据；报告仅是可重建视图。
- **语音与图片**：P0 浏览器本地 TTS 不上传语音数据；P1 若启用图片/OCR，图片默认只用于本次识别，不做人脸、声纹识别或模型训练，长期保存须独立授权并提供删除期限。
- **透明状态**：明确区分本地暂存、服务端已提交、同步中和失败；在正式宿主写入上线前不得承诺云端长期记忆。

### 8.2 教材与内容版权

- 教材目录、封面、正文、插图、音频和题目必须分别记录来源、版本、许可范围和可用状态。
- 未完成授权审查的第三方教材只能展示必要元数据或由用户本地导入，禁止随应用打包、公开分发、建立可下载镜像或用模型还原整本内容。
- AI 讲解应生成原创的解释、例子和图示；引用教材只取完成当前学习动作所必需的最小片段，并保留页码/章节锚点。
- 用户上传内容必须声明合法持有；系统提供删除和到期清理，不因上传自动获得再分发或训练授权。
- 题库和 AI 变式题必须区分；未完成答案、授权与知识映射复核的题目不得标为正式题库 active 内容。

### 8.3 未成年人和 AI 内容安全

- 默认采用未成年人安全模式、年龄适配语言和保守外链策略；不投放基于未成年人画像的广告，不提供公开排名、陌生人社交或诱导付费机制。
- 对孩子只描述可观察行为，不贴“懒、基础差、注意力差”等标签；家长反馈不得制造焦虑。
- AI 输出必须可反馈、可举报、可重新生成；高风险或无法核验内容应降级为人工确认，而不是高置信作答。
- 教材、OCR、网页、题干和参考答案均视为不可信材料，必须防提示注入；富文本采用白名单净化与 CSP，禁止不可信内容直接进入 `innerHTML` 或脚本上下文。
- 若未来启用组件 26，报告发布前必须经过监护人复核；若未来启用组件 37，运行结果仍只能作为 raw candidate，必须走 kernel closure、Schema、24 与宿主 commit。

## 10. UI Design Draft

### 10.1 视觉方向

- **设计语言**：Editorial / magazine，把教材、批注和学习证据组织成有阅读节奏的编辑式页面；清晰、温和、专注，不做低幼卡通化，也不做高压“刷题后台”。
- **核心色板**：纸张暖白 `#F6F1E7`（页面底色）、墨黑 `#20231F`（正文与主控件）、松针绿 `#2F6B57`（主行动与稳定状态）、朱砂橙 `#D96C3B`（提醒与纠错）、标注黄 `#E8C35A`（教材划线、证据引用）。正确/待复测/需帮助同时使用图标与文本，不仅依赖颜色。
- **字体**：标题、课程导语与教材批注采用“霞鹜文楷”；导航、正文、数字、状态和控件采用“IBM Plex Sans”。字体加载失败时必须有可读的系统字体回退，不阻断学习。
- **版式**：以大标题、细分隔线、页码感、边注和留白建立杂志阅读节奏；减少通用圆角卡片堆叠，主行动仍必须清晰可达。
- **信息密度**：学生端一次只突出一个主动作；复杂证据、来源和状态放入可展开详情。
- **反馈语气**：先描述行为证据，再说明下一步；避免“你真棒”“基础差”“粗心”等空泛或标签化表达。

### 10.2 桌面端布局：非对称三栏学习桌

- **左栏（窄）**：教材目录、章节、页码与学习进度，视觉上像书籍目录和边注区。
- **中栏（宽）**：作为主学习画布，展示本地 PDF 教材、微课堂步骤、练习或知识路径；保持最大阅读面积。
- **右栏（中等）**：AI 聊天、上下文引用、TTS 控制、当前唯一任务和候选/已提交状态。
- 三栏比例不做机械等分，建议约 18% / 54% / 28%；Quiz 或图谱模式可扩大中栏，但始终保留学习对象与返回路径。

### 10.3 手机 H5 布局：教材主画布 + 底部任务轨道

- 教材/微课堂占据主画布，顶部以轻量栏固定当前教材、章节和页码，不用多标签页切碎阅读。
- 底部任务轨道承载当前唯一动作、AI 输入、快捷提问与 Quiz 提交；可半屏展开聊天，但不得遮挡教材锚点和退出按钮。
- 教材选区、AI 回复和练习在同一上下文中串联；展开/收起或键盘弹起后不得丢失选区、草稿与学习进度。
- 图谱默认显示“当前点—前置—下一步”的聚焦路径，完整自由缩放图作为次级入口。

### 10.4 关键页面状态

所有关键页面必须设计：加载、空数据、演示教材、本地 PDF 未选择、无授权、能力未启用、生成中、可取消、失败重试、版本冲突、待提交、提交成功、同步中和安全拦截状态。
